# 二进制里的取值表

## 判据

- 源码里只有字段名、没有取值表时，表在二进制的字符串常量区。先按字节搜，不先断言「文档没有」。
- `strings` 加 `-e l` 或转 GB18030 过滤，对含中文的 Windows 二进制通常全空：针的字节编码与提取出的字节流不一致。全空不证明表不存在。
- 判据取「命中文件数 > 0」，不取「输出非空」：后者在 `iconv` 失败时也是空。

## 步骤

1. 列候选二进件：按体积降序取前十几个（`.exe` / `.dl` / `.pyd`）；几十 MB 整个读入内存可行。
2. 对每个候选词造两种针：UTF-8 字节与 UTF-16LE 字节。
3. 对每个文件 `search` 求全部命中位置。
4. 取命中处前后各约千字节，按对应编码解码。
5. 解码串里相邻的同类标签即枚举全表；紧接在前的枚举名就是字段的类型名。

## 坑

- 解码切片的上下界必须 clamp：命中只有几处时写死上界会报 bounding index。
- 同一词在一个文件里命中多次，只取前几处解码，不必全解。
- UTF-16LE 切片的两个字节要按低字节在前拼成码位；解码时跳过代理区与替换符。
- 枚举标签在字符串表里通常紧拼在一起、无分隔，靠语义切词；切出的每个词都要与已知取值对照，不能只靠字形猜。
